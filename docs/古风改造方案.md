# 「悦听」→「弦歌」古风改造方案

> 目标：把现有"黑酷炫"在线音乐网站改造为**古风诗词音乐站**——
> 收录古风纯音乐与古诗配乐朗诵，为每首诗打造"意境播放页"，
> 并接入 AI 能力实现"古诗转音乐"。
> 技术栈不变：Vue3 + SpringBoot + MySQL，现有架构全部复用。

---

## 〇、修订（2026-10-02）：以诗为主体的信息架构

方向定调：**这是一座古诗欣赏网站，音乐是佐诗的茶**。
不再沿用"发现音乐 / 歌曲库 / 歌手"的传统音乐站导航，
信息架构改为以**诗、诗人、朝代、诗人故事**为路线：

```
首页「今日」     今日一诗（按日期轮换）· 名句签 · 意境入口
诗选「诗库」     按朝代（先秦/魏晋/唐/宋）/ 体裁 / 情绪（月夜/田园/送别…）浏览
诗人            诗人名录 → 诗人页：生平故事（叙事长文）· 名句 · 存诗
意境页（核心）   一首诗一页：竖排诗行 · 古画意境 · 配乐朗诵 · 注/译/赏 · 感悟
书斋「我的」     收藏的诗 · 我的选集（原歌单转型）· 我写的感悟
音乐（辅助）     播放器常驻但不喧宾：朗诵配乐 / 纯音乐 / AI 谱曲皆服务于诗
```

配套数据模型：新增 `poet`（诗人：字/号/朝代/生平/故事）、`poem`
（诗：诗行/注/译/赏/情绪/体裁），`song` 增加 `poem_id` 挂到诗上成为
"诗之音轨"；原 singer 语义淡出，页面层不再作为一级导航。

以下原文写于以音乐为主体的阶段，作为历史参考保留；
分阶段实施以本修订为准。

## 一、想法评价

**结论：方向很好，值得做。** 三个点逐一评估：

| 想法 | 评价 |
| --- | --- |
| 古风视觉改造 | ✅ 性价比最高。现有 CSS 已全部走 design token（CSS 变量），换主题是系统性改一遍变量 + 字体 + 纹理，不是推倒重来 |
| 古诗配乐朗诵 + 意境播放页 | ✅ 这是**最与众不同的点**。市面上的音乐站课程项目 99% 是网易云仿站，"一首诗一个意境页"有辨识度，答辩时记忆点强 |
| 古诗转音乐（AIGC） | ⚠️ 亮点但风险最高。免费托管 API 不可靠（MusicGen 的 HF 免费 API 已关闭），可行的路是**开源模型 ACE-Step 本地/私有部署**。建议做成可选增强模块，且提供"预生成"兜底 |

**必须提前想清楚的三件事（都已找到对策）：**

1. **版权**：朗诵音频绝不能扒喜马拉雅/电台的（全部有版权）。对策：用 TTS 自己生成——朗诵者就是软件，零版权风险。纯音乐用 Pixabay（免署名可商用）；意境背景图用宋元古画的高清扫描件（公有领域）。
2. **"转音乐"的可行性**：2026 年的现状是没有稳定的免费音乐生成 API。开源的 ACE-Step 1.5（MIT 协议，支持中文歌词/结构标签，10 秒~4 分钟，消费级显卡可跑）是最现实的载体；没有 GPU 时退化为"离线预生成"，功能照样能演示。
3. **内容量**：古风站的说服力全在内容质感。方案用脚本批量生产（诗来自开源数据集、音频自动合成、混音自动化），不靠手工一篇篇做。

## 三、总体设计

### 3.1 品牌与视觉系统

站名建议 **「弦歌」**（弦歌不辍；副标题"诗乐雅集 · 古诗配乐欣赏"）。

设计 token 全面替换（前端 `src/assets/styles/main.css` 已是变量化主题，改造成本可控）：

| Token | 现值（暗黑炫彩） | 改为（古风） |
| --- | --- | --- |
| 背景 | 深蓝黑 `#0b0d14` | 宣纸暖白 `#f5efe2`，叠加宣纸纹理 |
| 面板/卡片 | 深灰面板 | 笺纸米色 `#fbf7ec` + 细描边（仿装订线） |
| 正文 | 亮灰白 | 墨色 `#2a2620` |
| 主强调色 | 紫粉渐变 | 朱砂 `#a63a2b`（印章红） |
| 次强调 | 霓虹紫 | 黛青 `#2f4f4f` / 竹青 `#6b8e23` |
| 点缀 | 霓虹光晕 | 泥金 `#b8860b` 描线、印章元素 |
| 字体 | Inter/系统无衬线 | 标题：霞鹜文楷；正文：思源宋体 |
| 圆角/阴影 | 大圆角霓虹 | 小圆角细描边，阴影极淡 |

标志性视觉元素：
- **竖排诗行**：诗详情页诗句用 `writing-mode: vertical-rl` 从右向左排（配横向移动端降级）
- **印章 logo**：方形朱文印"弦歌"二字替代现在的圆形渐变 logo
- **意境背景**：每首诗配一幅古画（按诗的情绪匹配山水/花鸟/雪景），低饱和 + 宣纸蒙版
- **交互细节**：hover 墨晕扩散、进度条做成卷轴样式、歌单卡片做笺纸折角

### 3.2 数据模型扩展（新增 1 表 + 2 字段 + 音频本地化）

```
新表 poem（诗）：
  id, title, author, dynasty, paragraphs(JSON 诗行), translation(译),
  appreciation(赏析), mood(情绪标签：月夜/边塞/田园/离别/咏怀…),
  painting_url(意境古画), poem_no(选诗序)

song 表加字段：
  poem_id BIGINT NULL   → 关联到诗（NULL=纯音乐不配诗）
  type VARCHAR(20)      → 'instrumental'纯音乐 / 'recitation'朗诵配乐 / 'generated'AI生成
  audio_path VARCHAR    → 本地相对路径（替代外链 URL）

singer 表语义微调：歌手机构改为"朗诵者/乐府"，如"文楷(TTS·女声)"
```

**音频存储方式升级**（现在是 SoundHelix 外链，古风内容必须自主可控）：
- SpringBoot 新增静态资源映射：`/api/audio/**` → 本地 `backend/audio/` 目录
- mock 模式（GitHub Pages）在 `frontend/public/audio/` 放一份精简版（60~90 秒切片，朗诵 64kbps 单声道 + 纯音乐 96kbps，单文件 ≤1MB，16 首 ≈ 12MB，仓库可承受）
- 数据库 `song.url` 存相对路径，前端按运行模式拼不同 base

### 3.3 内容生产管线（离线脚本 `tools/`，Python）

一次性/可重跑的生成脚本，产出 = 种子 SQL + 音频文件：

```
tools/build_content.py
  1. 选诗：从 chinese-poetry 数据集按 mood 精选 24 首（每情绪 3~4 首），
     抽取正文/作者/朝代 → 生成 poem 表 INSERT
  2. 配乐：从 Pixabay 下载古筝/笛子/琵琶曲目，ffmpeg 切 60-90s、
     按情绪归一化音量 → backend/audio/bgm/
  3. 朗诵：edge-tts 逐诗生成（男声云希/女声晓晓按诗气质选择）→ backend/audio/tts/
  4. 混音：ffmpeg 把朗诵轨(0dB) + BGM 轨(-14dB 侧链避让人声) 合成
     "配乐朗诵版" → backend/audio/mixed/
  5. 意境图：按 mood 从本地古画库（ Wikimedia 高清扫描，预先下载裁剪）映射
  6. 汇总生成 data.sql（幂等 INSERT IGNORE，现有机制复用）
```

### 3.4 意境播放页（核心页面，原歌曲详情页改造）

```
┌────────────────────────────────────────────┐
│  [古画背景 · 低饱和 + 宣纸蒙版 · 缓慢 Ken Burns]  │
│                                            │
│   ┌──竖排诗行(从右到左)──┐   ┌─卷轴播放器─┐   │
│   │ 空山新雨后            │   │ ▶ 朗诵/纯音乐│  │
│   │ 天气晚来秋            │   │ 进度·模式    │  │
│   │ 明月松间照            │   └───────────┘   │
│   │ 清泉石上流            │   [AI·为此诗谱曲]  │
│   └─────────────────────┘                    │
│  作者/朝代 · 注 · 译 · 赏（Tab 切换）          │
│  同情绪诗推荐 · 评论                           │
└────────────────────────────────────────────┘
```

- 播放器支持**朗诵版 / 纯音乐版 / AI 生成版**三个音轨切换（同一首诗三份音频）
- "播放全部"= 按情绪串成的诗乐长卷
- 意境图随播放进度缓慢平移（Ken Burns 效果），营造"人在画中游"

### 3.5 古诗转音乐（AIGC 模块）

```
用户点击「为此诗谱曲」
  → POST /api/ai/music/generate { poemId }
  → 后端 AiMusicService：
     1. 查缓存：generated 表是否已有该诗 → 有则直接返回
     2. 意象→提示词：规则字典把诗的 mood/关键词映射为音乐描述
        例：{月夜,静} → "Chinese guzheng, xiao flute, slow, peaceful, night"
        {边塞,壮} → "war drums, guqin, majestic, epic"
        （可选升级：接 LLM API 做诗→prompt 翻译，规则版零依赖先落地）
     3. 调 ACE-Step（本地 CLI 或自部署推理服务）生成 60-90s
     4. 落盘 backend/audio/generated/，登记 song(type=generated)
     5. 前端轮询任务状态 → 完成后播放器直接可播
```

**降级策略**（重要，保证演示永不翻车）：无 GPU / API 不可用时，按钮变为"领取预生成曲库"——Phase 1 管线已为每首诗离线生成一版 AI 曲风配乐，接口只做登记返回。这样功能链路完整，等有 GPU 再把"实时生成"打开。

## 四、分阶段实施

| 阶段 | 内容 | 工作量 | 验收标准 |
| --- | --- | --- | --- |
| **P0 视觉换肤** | 设计 token 替换、古风字体、印章 logo、登录页/发现页/卡片重绘 | 1~2 天 | 全站无残留暗黑配色；登录页/发现页截图对比 |
| **P1 数据与音频管线** | poem 表、选诗脚本、TTS 朗诵、混音管线、后端 /audio 静态服务、新 data.sql | 2~3 天 | MySQL 有 24 首诗；朗诵配乐可直接 curl 播放；mock 模式同样出声 |
| **P2 意境播放页** | 诗详情页（竖排诗行/古画背景/三音轨切换/注译赏）、诗库页、按情绪筛选 | 2~3 天 | 任一诗可从诗库进入意境页播放朗诵并看到配图与赏析 |
| **P3 AI 谱曲模块** | AiMusicService + 意象映射 + ACE-Step 接入 + 预生成兜底 + 前端任务流 | 3~5 天 | 任一诗可点击"谱曲"，30s~3min 内获得可用音轨（或预生成兜底） |
| **P4 打磨与部署同步** | 墨晕过渡动画、今日一首、搜索支持诗句全文、mock 精简音频入库、线上站点同步更新 | 1~2 天 | GitHub Pages 线上站点呈现古风版 |

总计约 9~15 天的逐步交付，每个阶段独立可验收，随时可以停在任一阶段（都保持完整可用）。

## 五、风险与对策

| 风险 | 对策 |
| --- | --- |
| edge-tts 非官方接口随时可能失效（403 token 问题历史频发） | 脚本一次性批量生成后音频即落盘，不依赖运行时可用性；备选 Azure TTS 免费额度 |
| 本机无 NVIDIA GPU，ACE-Step 实时生成不可行 | 预生成兜底 + 后期部署后端到 GPU 云主机再开启实时 |
| Pixabay 曲目与诗的情绪匹配度一般 | 脚本按 mood 建映射表人工校一轮；不行就用同一 BGM 降音量铺底，突出朗诵 |
| 竖排文字在移动端适配复杂 | `writing-mode` 仅在 ≥768px 启用，移动端退化为横排大字号 |
| 音频文件让前端仓库变大 | mock 模式只放 60~90s 精简切片（总 ≤15MB）；完整版只存 backend/audio 不进 git |
| 版权误用 | 三条红线：朗诵全部 TTS 自产、纯音乐仅 Pixabay 协议曲目、画作仅公有领域扫描件 |
